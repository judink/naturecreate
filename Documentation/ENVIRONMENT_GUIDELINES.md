## 1. 목표와 문서 사용법

### 1.1 최종 목표

사람이 생활하는 중세풍 마을, 서로 연결되는 경작지, 언덕·숲·들판·강·원경 산이 하나의 장소처럼 이어지는 탐험 가능한 환경을 만든다. 건물만 늘어놓거나 나무로 빈 공간을 일괄 덮는 방식은 피한다. 배치에는 통행, 주거, 농업, 작업, 자연환경의 이유가 있어야 한다.

사용자가 중요하게 본 기준은 다음과 같다.

- 마을은 도로와 집의 관계가 명확하고, 집 입구가 길에 가까워야 한다.
- 집 주변에는 담장·텃밭·생활 소품·풀·나무가 어울리게 있어야 한다.
- 논밭은 큰 면적을 구성하는 서로 인접한 필지로 읽혀야 한다.
- 숲은 빽빽한 내부와 부드러운 가장자리를 갖되, 전체가 나무벽처럼 균일하지 않아야 한다.
- 초원은 낮은 풀, 키 큰 풀, 꽃이 서로 다른 규모의 군집으로 섞여야 한다.
- 자연 에셋은 NatureManufacture 데모의 원본 형태와 머티리얼 품질을 살려야 한다.
- 낮에는 햇빛과 그늘의 대비가 있고, 밤과 새벽에는 밝기가 자연스럽게 이어져야 한다.
- 실제 캐릭터 시점에서 접지, 출입, 그림자, 원거리 표현을 검수해야 한다.
- 밀도를 늘릴 때도 프레임 비용을 관리해야 한다.

### 1.2 무엇을 확정 기준으로 읽을 것인가

- **설계 기준**: 사용자의 요구를 다음 작업에서도 지켜야 할 형태로 정리한 내용이다.
- **현재 확인값**: 기준일에 실제 씬·소스·적용 보고서에서 확인한 값이다. 다른 맵에 그대로 복사할 보편적인 정답은 아니다.
- **후속 검수 항목**: 요구는 있었지만 현재 문서 작성에서 개별 모델·모든 배치까지 확인하지 않은 사항이다. 특히 특수 건물의 제작 완료와 성능 목표 달성을 임의로 확정하지 않는다.

대화 중 등장한 배율 지시는 당시 상태에 대한 상대값이다. `1.3배`, `2배 밀도`, `갈대 2/3 크기`를 현재 결과에 다시 누적 적용하지 않는다. 현재 채택한 데모 기준과 최종 씬을 우선한다.

## 3. 아트 방향과 에셋 사용

### 3.1 중세 마을과 자연의 품질

마을 건축과 소품에는 중세·레트로 분위기를 유지한다. 다만 자연 에셋까지 임의로 심하게 단순화하거나, 원본 메시를 비균일하게 찌그러뜨리거나, 텍스처 품질을 일괄 낮추지 않는다. 최종 자연 표현의 기준은 NatureManufacture 데모에서 보인 나무·풀·꽃·숲 바닥이다.

레트로 화면 효과의 강도와 원본 에셋의 품질은 별개로 관리한다. 원본 품질 비교는 우선 화면 효과를 Off로 하고 수행한다.

### 3.2 에셋 선택 원칙

- 초기에는 LOLIPOP/Sketchfab, 무료 꽃·풀·중세 소품 후보를 조사했다.
- 현재 식생·나무·바위와 자연 지면의 주요 기준은 `Assets/NatureManufacture Assets/`의 팩이다.
- 원본 메시, 원본 머티리얼, 원본 텍스처 연결과 LOD를 우선 사용한다.
- 원본과 다르게 보이면 메시 외에 조명, 노출, 컬러, 알파 클리핑, 그림자, LOD, 거리 페이드, 화면 효과를 먼저 확인한다.
- 프로젝트용 조정이 필요하면 별도 변형 에셋을 만들고 변경한 속성을 명시한다.
- 에셋 팩 원본 전체에 일괄 변경을 가하지 않는다.
- 모든 나무를 fir 한 종류로 통일했던 방향은 현재 기준이 아니다.

### 3.3 스케일과 텍스처

- 자연 모델은 균일 스케일로 비례를 보존한다.
- 최적화된 메시가 있다는 이유만으로 먼 거리용 메시를 근거리에도 고정 사용하지 않는다.
- 모델의 UV가 늘어지거나 월드 스케일과 타일링이 맞지 않으면 먼저 UV·매핑을 고친다.
- 원본 데모의 크기와 현재 캐릭터 기준 크기를 함께 비교한다.

## 4. 지형·언덕·배경 산

### 4.1 마을 가까운 지형

- 마을 바로 주변은 완만한 언덕과 국지적인 요철이 이어지는 지형으로 만든다.
- 노이즈를 이용하되, 건물 바닥·도로·경작지·강의 기능을 깨지 않는 마스크를 적용한다.
- 마을 전체를 완벽한 평면으로 만들지 않는다.
- 반대로 집 바로 뒤에 과도하게 솟은 산이나 깎아낸 절벽을 만들어 답답하게 하지 않는다.
- 높이 변경 후 건물, 담장, 농작물, 식생, 바위의 접지를 다시 확인한다.

### 4.2 배경 산

- 배경 산은 근거리 생활 지형과 별도로 구성할 수 있다.
- 한 방향에만 산이 보이지 않도록 사방의 원경 구도를 검토한다.
- 높이맵·DEM 기반의 형태와 능선이 있는 산세를 활용한다.
- 사용자 표현의 `rigged`는 문맥상 능선이 살아 있는 거친 산 형태에 대한 요구로 취급한다. 캐릭터 리깅 요구로 해석하지 않는다.
- 잘린 단면·지형 끝·산 메시의 열린 면이 마을 중앙을 향하지 않게 한다.
- 근경 언덕, 중경 숲, 원경 산이 거리 층을 만들도록 배치한다.
- 회색 암석만 보이지 않도록 낮은 경사·낮은 고도에는 초록 지표를 섞는다.
- 작은 암석 텍스처가 반복되는 모아레·바둑판 느낌을 줄인다. 큰 색 변화와 세부 텍스처 규모를 분리한다.
- 안개로 원경을 희게 지워버리지 않는다. 산의 실루엣과 거리 차이가 남아야 한다.

### 4.3 경계 검수

지형 타일, 추가 산, 머티리얼, 높이맵 사이에 직선 경계가 생기지 않는지 검수한다. 경계를 숨기기 위해 식생만 과도하게 추가하지 않는다.

## 5. 마을 구조와 건물

### 5.1 배치 설계

- 최종 마을 재설계의 출발점은 사용자가 제공한 `stanmatthew.json`과 지도 이미지다.
- 사용자가 수정한 웹 배치도를 실제 Unity 배치에 반영한다.
- 큰 변경은 HTML 선 도면과 배치 미리보기에서 먼저 검토한다.
- 집 사이를 넓히고 마당을 확보하라는 초기 요구와, 큰 공터를 없애도록 더 조밀하게 하라는 후속 요구를 함께 반영한다.
- 최종 기준은 **각 집의 생활 공간은 확보하되, 이유 없는 큰 공터와 길에서 떨어진 집을 줄이는 것**이다.
- 도로·건물 간격을 함께 조정한다. 집만 빈 땅에 무작위로 추가하지 않는다.
- 기존 도로변의 빈 구간에 건물 전면을 배치해 가로의 연속성을 만든다.
- 새로 추가한 주택에도 마당, 담장, 출입 동선, 소품, 지면 처리를 함께 적용한다.

### 5.2 건축 형태

- 사용자가 제공한 `medival-house.zip`의 중세 건축 형식을 참고한다.
- 동일 건물 복제만 반복하지 않는다.
- 지붕, 층수, 입면, 목조 구조, 석재·회벽 비중, 색상, 창문·문 구성에 변형을 준다.
- 벽과 지붕의 UV 늘어짐을 방치하지 않는다.
- 건물별 머티리얼 변화는 전체 마을의 재료·시대감을 유지하는 범위에서 적용한다.

### 5.3 주택 입구와 마당

- 현관은 도로 가까이에 두고, 앞문에서 길까지 자연스럽게 이어지게 한다.
- 집 주위의 자주 밟히는 공간은 흙바닥으로 페인팅한다.
- 흙길이 건물 가까이 닿아야 하며, 집 옆이 일률적인 잔디 카펫처럼 남지 않게 한다.
- 출입구·계단·문 앞을 풀, 바위, 담장, 소품으로 막지 않는다.
- 벤치, 상자, 항아리, 저장물 등은 벽 가까이에 기능별로 모은다. 마당 한가운데 일정 간격으로 흩뿌리지 않는다.

## 6. 도로와 출입 동선

### 6.1 도로 형태

- 마을 주도로, 골목, 목책 안쪽 생활도로, 바깥 농로가 끊기지 않도록 연결한다.
- 목책을 따라 안팎에 순환 동선을 만든다.
- 집을 불필요하게 한 바퀴 감싸는 우회 도로는 만들지 않는다. 필요한 구간은 집 뒤로 간결하게 통과시킨다.
- 문, 목책 출입구, 농지 진입로, 다리와 도로를 함께 설계한다.
- 도로 위를 가로지르는 잔여 울타리나 옛 농지 구조물을 제거한다.

### 6.2 도로 표현

- 기본은 흙길이며 작은 자갈과 지면 변화로 디테일을 준다.
- 과거 실험했던 도로의 수레바퀴 자국은 제거하는 방향이 채택됐다.
- 자갈 흙길 무료 텍스처 후보를 여러 차례 시험했지만, 사용자는 후보 교체 전 상태로 복귀를 요청했다.
- 이후 NatureManufacture 자연 에셋 전환이 있었으므로, 옛 텍스처 후보를 현재 씬에 자동으로 재적용하지 않는다.
- 현재 씬의 도로 머티리얼을 기준으로 변경 전후 비교한다.
- 흙길과 grass 텍스처 경계는 자연스럽게 블렌딩한다.
- 풀은 블렌딩된 길 가장자리까지 가까이 자랄 수 있지만, 이동하는 길 중심은 비운다.

## 7. 논밭·텃밭·농작물

### 7.1 큰 경작지의 형상

사용자는 서로 떨어진 이상한 다각형, 억지로 다양하게 만든 필지, 작은 조각이 흩어진 배치를 반복해서 수정 요청했다. 핵심은 도형 종류의 개수가 아니라 **농지가 서로 맞닿아 하나의 경작 영역을 이루는 것**이다.

- 사용자 제공 항공사진처럼 인접 필지가 경계를 공유한다.
- 사각형, 사다리꼴, 완만한 곡선 경계, 불규칙 다각형을 지형·길에 맞게 섞는다.
- 길과 농지 경계가 서로 설명될 수 있어야 한다.
- 무의미한 삼각형 잔여 필지나 아주 가는 띠 모양 경작지를 만들지 않는다.
- 주택가와 경작지가 만나는 구조를 만든다.
- 사용자가 직접 편집한 최신 필지 경계를 우선한다.
- 논밭을 “안쪽”으로 옮겨 달라는 요청은 **마을 쪽 빈땅으로 이동**하는 의미로 명확히 확인됐다.

### 7.2 집 뒤 텃밭과 외곽 농지

- 집마다 작은 텃밭이 있는 방향은 유지한다.
- 집 뒤 텃밭에 주택 담장과 별개로 울타리를 다시 둘러 이중으로 만들지 않는다.
- 외곽 큰 경작지는 목책 바깥에 인접해 배치한다.
- 목책과 바깥 농로 사이의 좁은 잔여 공간은 실제 필지가 아니면 농지 텍스처로 칠하지 않는다.

### 7.3 페인팅·농작물·울타리의 일치

동일한 최신 필지 데이터를 아래 항목에 공통 사용한다.

1. 지면의 경작 텍스처 영역.
2. 농작물 배치 영역.
3. 필지 경계 울타리.
4. 농지 진입구와 농로 제외 영역.
5. 일반 풀·나무·바위의 배치 금지 영역.

필지만 이동하고 텍스처, 작물, 울타리가 예전 위치에 남는 상황을 금지한다. 구멍이 있는 폴리곤과 도로가 잘라내는 영역도 반영한다.

`논밭`이라는 대화 표현만으로 모든 필지를 물이 고인 논으로 바꾸지 않는다. 현재 경작지의 작물·토양 표현을 유지하고, 수전 농업을 추가할 때는 별도 설계를 한다.

## 8. 돌담·나무 울타리·목책

### 8.1 주택 담장

- 집을 감싸는 담장은 돌담으로 통일한다.
- 붙어 있는 집 사이에는 각 집별 평행 담장 두 줄 대신 공유 경계 담장 한 줄을 둔다.
- 문과 길로 이어지는 출입구를 확보한다.
- 사용자가 만든 gate pier 모듈을 담장 끝과 출입구에 어울리게 활용한다.
- 새 주택과 기존 주택에 같은 기준을 적용한다.
- 집 뒤 텃밭에 추가 울타리를 이중으로 만들지 않는다.

### 8.2 직접 제작한 돌담 에셋

- 너무 투박한 초저폴리 형태에서 개선한 돌 모양과 질감을 사용한다.
- 돌마다 약간의 크기·형상 차이를 주되, 모듈 끝 연결이 깨지지 않게 한다.
- 내부 채움재·모르타르가 돌 바깥으로 튀어나오지 않도록 안쪽에 넣는다.
- 직선 A/B, 코너, 기둥 모듈을 활용한다.
- Blender 원본은 선택·편집 가능한 상태로 유지한다.
- Unity 재수출 후 스케일, 축, 피벗, 머티리얼, LOD 이름, 콜라이더를 확인한다.

제작 원본: `Art/RetroStoneFence/Retro_Stone_Fence.blend`.

### 8.3 일반 나무 울타리

- 서로 다른 두 종류가 섞여 어색하다는 지적이 있었으므로 선택한 한 가지 계열로 통일한다.
- 도로 위에 울타리가 남거나 교차하지 않도록 한다.
- 농로를 따라 필요한 필지 경계가 빠지지 않았는지 검사한다.
- 카메라 각도에 따라 보였다 사라지는 경우 중복 면, 법선, LOD, 오클루전과 잘못된 배치를 함께 점검한다.

### 8.4 마을 외곽 목책

- 본마을 주택군 가까이에 둥글고 부드러운 경계로 두른다.
- 북쪽 외딴집은 벽 밖 농가로 두고, 이를 감싸기 위해 목책을 길게 돌출시키지 않는다.
- 사용자가 웹 편집기에서 새로 그린 목책 라인을 기준으로 한다.
- 점이 너무 많은 자동 폴리곤을 강요하지 않는다. 처음부터 직접 다시 그리기와 점 편집을 지원한다.
- 안쪽 생활도로, 바깥 농로, 바깥 경작지를 함께 맞춘다.

## 9. 마을 생활 소품과 특수 건물

### 9.1 소품 배치 기준

- 집과 도로만 있는 비어 있는 마을을 피한다.
- 시장, 과수원, 공동 작업 공간, 물 사용 공간, 저장 공간, 가로등 등 생활 기능을 가진 구역을 만든다.
- 소품은 장소의 용도에 맞게 모아 배치한다.
- 집 옆 소품은 벽에 가깝게, 작업 도구는 작업 공간에, 판매 물품은 시장에 배치한다.
- 통행 공간을 유지하면서 알차고 풍성하게 꾸민다.
- 단순 원시 도형을 대충 조합한 듯한 소품 품질을 피한다.
- 무료 에셋 후보는 중복을 제거하고 팩별로 정리해 비교한다.
- Blender 검토 시 팩별 구역과 다음 팩으로 이동하기 쉬운 구성을 제공한다.

### 9.2 선택 이력

- 레트로 시장 소품을 우선 사용하려는 방향이 있었다.
- 당시 목록의 `4번 우물수레`는 제외 요청이 있었다.
- 당시 `12번 판타지 소품`은 레트로 분위기에 맞춰 텍스처를 수정하는 방향이었다.
- 번호는 당시 에셋 목록의 번호이므로 현재 다른 목록의 같은 번호에 자동 대응시키지 않는다.

### 9.3 특수 건물

사용자는 교회, 풍차 또는 물레방아 성격의 건물 같은 랜드마크를 원했다. 다음은 설계 시 지켜야 할 기준이며, 모든 해당 건물의 완성·설치를 이 문서가 보증하는 것은 아니다.

- 풍차는 바람을 받는 위치와 회전 공간을 확보한다.
- 물레방아는 강과 수로에 연결되는 기능을 고려한다.
- 교회 등 공공 건물은 마을의 시선·도로·광장 구조와 연결한다.
- 풍차와 물레방아는 다른 시설이므로 모델 선택 전에 구분한다.
- 사용자가 승인한 최신 배치도를 확인한 뒤 설치한다.

## 10. 강과 수변

- 강은 마을 바로 옆을 지난다.
- 위치는 지도 기준 **왼쪽·서쪽**으로 수정하는 방향이 채택됐다.
- 웹 설계에만 표시하고 끝내지 않고 Unity 지형·수면·강변·다리와 연결한다.
- 강의 배치 마스크를 식생·농작물·바위 생성에 반영한다.
- 강변 풀과 관목은 수면 위에 떠 있지 않게 한다.
- 수변 시설과 물레방아를 추가할 때 기존 강 경로를 먼저 확인한다.

## 11. 지면 텍스처와 블렌딩

### 11.1 현재 지형 레이어 의미

| 인덱스 | 용도 |
|---|---|
| 0 | Meadow grass |
| 1 | Forest ground leaves / 낙엽 바닥 |
| 2 | Meadow soil / 마른 흙 |
| 3 | 산·암석 지표 |
| 4 | Forest ground grass |
| 5 | 젖은 흙 |
| 6 | 경작지 이랑 |

인덱스만 맹신하지 않는다. TerrainLayer를 재구성한 뒤에는 반드시 실제 에셋 연결을 다시 확인한다.

### 11.2 질감과 색상

- 지면 grass 텍스처는 배치된 풀과 색감이 어울려야 한다.
- 지나치게 옅은 잔디 지면 위에 어두운 풀만 올려놓는 대비를 피한다.
- 전체 지면이 한 가지 색으로 평평해 보이지 않게 한다.
- 풀과 흙을 서로 다른 크기의 노이즈로 부드럽게 섞는다.
- 숲 내부는 낙엽·숲 흙이 드러나고, 바깥은 초원으로 이어져야 한다.
- 미끌미끌하거나 젖은 플라스틱처럼 보이면 Smoothness, Roughness 변환, 마스크 채널, 노멀과 반사광을 확인한다.
- AI 생성 텍스처도 실험했지만 현재 자연 품질의 기준은 NatureManufacture 원본과 데모 표현이다.

### 11.3 현재 노이즈 블렌딩 방식

`StanmatthewGroundBlend.cs`는 큰 색 변화와 세부 패치를 나누어 풀·흙을 섞는다. 현재 구현에는 약 33m, 9m, 2.7m 규모의 노이즈와 위치 왜곡이 사용된다. 보호 영역 가장자리에서 블렌딩을 줄이며 도로·농지에 흙 혼합이 새지 않게 한다.

숲 바닥은 별도 숲 밀도 마스크로 낙엽 레이어를 늘린다. 초원 블렌딩과 숲 바닥 작업의 실행 순서를 바꾸면 후속 작업이 지워질 수 있으므로 재생성 시 데이터 의존성을 확인한다.

## 12. 풀·갈대형 풀·꽃

### 12.1 기본 풀의 최종 방향

- grass 텍스처가 칠해진 생활 가능 지면에 큰 빈 구멍이 생기지 않게 낮은 풀을 깐다.
- 도로, 건물 바닥, 농작물 필지, 수면은 제외한다.
- 풀을 균일하게 덮으라는 요구는 모든 종을 같은 밀도로 뿌리라는 뜻이 아니다.
- **낮은 풀의 기본 피복은 연속적이고, 키 큰 풀과 꽃은 군집으로 변화**하도록 한다.
- 모든 풀이 너무 크고 빽빽한 상태는 이후 수정 대상이 됐다.
- 최종 크기·종 비율은 NatureManufacture 데모의 자연스러운 혼합을 기준으로 한다.

### 12.2 크기·변형·색·바람

- 개체마다 높이와 폭에 차이를 주어 정돈되지 않은 야생 느낌을 만든다.
- 랜덤 범위의 최솟값이 너무 작아 풀이 거의 보이지 않는 상태를 피한다.
- 녹색 일색을 피하고 일부 갈색빛·마른 풀을 자연스럽게 섞는다.
- 색 변화는 공간 노이즈와 군집으로 구성한다. 개체마다 극단적인 밝기 차이를 무작위로 주지 않는다.
- 바람에 흔들리는 효과를 적용하되 뿌리는 고정되어 보여야 한다.
- 원본 메시와 머티리얼로 전환한 이후에는 예전 폭 1.5~2배 지시를 일괄 재적용하지 않는다.

### 12.3 갈대처럼 보이는 키 큰 풀

- 마을 가까이에서도 볼 수 있어야 한다.
- 너무 크게 키우거나 전역을 덮게 하지 않는다.
- Perlin Noise 기반 군집으로 배치한다.
- 낮은 풀 사이에서 높이 변화를 만드는 역할을 한다.
- 숲 깊은 곳에서는 비중을 크게 줄인다.
- 여기서 `갈대풀`은 대화에서 키 큰 이삭형 풀을 부른 표현이다. 모든 군집을 수생 갈대 서식지로 해석하지 않는다.

### 12.4 꽃과 잡초

- 꽃도 실제 에셋을 사용하며, 듬성듬성 한 개씩만 뿌리지 않는다.
- 종별로 작은 군락을 만든다.
- 낮은 풀·키 큰 풀·흰 꽃·노란 꽃·붉은 꽃 등의 비율이 지역별로 달라지게 한다.
- 쐐기풀은 제거 요청이 있었으므로 재도입하지 않는다.
- 꽃과 갈대는 서로 완전히 동일한 노이즈 패턴을 공유하지 않는다.

### 12.5 주택과 도로 가장자리

- 집 주변도 기존 일반 풀 크기로 배치한다. 지나치게 작은 장식용 풀로만 대체하지 않는다.
- 벽에 가까이 붙는 것은 허용하지만 현관·계단·통행은 비운다.
- 마을 사이 빈땅과 목책·농로 사이 grass 표면에도 기본 풀을 빠짐없이 연결한다.
- 도로 외곽 블렌딩 띠를 과도하게 비워 넓은 민머리 테두리가 생기지 않게 한다.

### 12.6 접지와 빈 구멍

- 공중에 뜬 느낌은 모델 피벗·메시 하단·스케일·Terrain 높이를 함께 확인한다.
- 높이 변경 후 재접지한다.
- 삼각형·직선 모양으로 풀이 없는 곳은 자연스러운 노이즈로 간주하지 않는다.
- 이전 농지 마스크, 도로 폴리곤, 삼각분할, 좌표 변환, 디테일 거리와 머티리얼 페이드를 점검한다.
- 거리 페이드로 사라지는 풀과 실제 배치 누락을 구분한다.

## 13. 나무 군집과 숲 내부

### 13.1 군집 구조

사용자가 제시한 절차를 기본으로 한다.

1. Perlin Noise 등으로 숲 밀도 지도를 만든다.
2. 밀도가 높은 곳에 나무를 집중 배치한다.
3. 군집 안에서도 간격·크기·회전을 변화시킨다.
4. 가장자리에 작은 나무, 관목, 바위를 섞는다.
5. 마을, 길, 농지에 별도 보호 마스크를 적용한다.

군집 내부는 빽빽해도 군집 사이와 가장자리에는 열림이 있어야 한다. 전체 외곽이 일정한 높이와 두께의 나무벽처럼 보이면 형태를 다시 조정한다.

### 13.2 어디에 심는가

- 숲은 아주 먼 곳부터 시작하지 않고 마을·논밭 바로 바깥까지 접근할 수 있다.
- 마을 내부의 적절한 공터와 집 주변에도 나무를 둔다.
- 도로 양쪽 울타리 바깥에는 가로수처럼 이어지는 배치도 활용한다.
- 건물, 담장, 농지, 문, 길, 강을 침범하지 않는다.
- 외부 숲과 마을 안 나무에 동일한 고밀도 규칙을 적용하지 않는다.

### 13.3 NatureManufacture 샘플 숲의 채택 요소

- 숲 내부에는 넓고 풍성한 수관의 성목이 많이 있어야 한다.
- 원본 성목을 지나치게 축소해서 듬성한 작은 나무처럼 보이게 하지 않는다.
- 내부는 수관이 겹치고 나무 아래에 그늘이 형성되어야 한다.
- 숲 바닥은 낙엽·숲 흙 위주로 바꾼다.
- 내부의 풀은 초원보다 성기고, 꽃·키 큰 풀은 훨씬 적다.
- 가장자리에서 낮은 나무와 초원 식생으로 부드럽게 전환한다.

### 13.4 현재 적용 스냅샷

| 항목 | 현재 값 또는 방식 |
|---|---|
| Terrain 나무 인스턴스 | 76,757개; 별도 씬/배치 나무를 포함한 전체 수는 아님 |
| 중심 성목 조정 | 기존 위치를 유지하면서 46,954개 인스턴스의 종류·스케일 조정 |

## 14. 관목·바위·자갈

### 14.1 배치 요구

- 나무와 grass만으로 자연을 구성하지 않는다.

- 마을 주변뿐 아니라 숲·들판 전반에서 돌을 자주 볼 수 있어야 한다.
- 작은 돌, 중간 바위, 큰 바위를 섞는다.
- 큰 바위는 일부 군집을 만들고, 작은 돌은 주변에 흩어진 동반 개체로 배치한다.
- 도로에는 별도 작은 자갈을 자연스럽게 배치한다. 들판용 큰 바위 규칙을 도로에 적용하지 않는다.
- 바위는 지면에 일부 묻혀 안정적으로 보여야 한다.

### 14.2 현재 추가 분포

`43 NATURE - forest and meadow scattered rocks`에 추가된 돌만의 수치다. 이전 마을 바위·관목·도로 자갈은 별도다.

| 분류 | 수량 |
|---|---:|
| 작은 돌 | 20,286 |
| 중간 바위 | 10,780 |
| 큰 바위 | 1,373 |
| 합계 | 32,439 |
| 숲 마스크 영역 분류 | 8,241 |

- NatureManufacture의 작은 돌 6종, 중간 바위 3종, 큰 바위 7종을 사용한다.
- 위치를 흔든 격자 후보와 주변 위성 개체로 넓은 분포와 작은 군집을 함께 만든다.
- 원본 메시·머티리얼·LOD를 사용한다.
- 큰 바위에는 충돌을 두고 작은 장식 돌에는 불필요한 콜라이더를 만들지 않는다.
- 적용 당시 최신 도로·필지·집·강·목책 보호 영역과 바위 반경의 충돌 검사 결과는 0건이었다. 지도가 바뀌면 다시 검사한다.

## 15. 하늘·낮밤·라이팅

### 15.1 하늘과 구름

- 움직이는 구름과 시간에 따른 하늘색 변화를 제공한다.
- Tenkoku 텍스처를 사용하는 현재 URP 어댑터를 기준으로 한다.
- Tenkoku의 Built-in 전체 렌더러를 그대로 이식한 상태라고 설명하지 않는다.
- 구름이 정지해 보이면 애니메이션 플래그, 속도, 머티리얼 연결, 활성 skybox를 확인한다.
- NatureManufacture 비교를 위해 고정 데모 조명을 썼던 단계는 있었으나, 현재는 낮밤 순환이 다시 활성화되어 있다.

### 15.2 낮의 요구

- 햇빛은 강하고, 그늘은 충분히 짙어야 한다.
- 주변광이 모든 면을 고르게 밝혀 입체감을 없애지 않게 한다.
- 원거리 나무에도 그림자와 명암이 남아야 한다.
- 블룸·후처리는 풍경을 개선하는 범위에서 사용하며, 흰 번짐으로 재질을 덮지 않는다.

### 15.3 밤과 새벽의 요구

- 달빛이 낮처럼 밝지 않아야 한다.
- 달빛이 약해지는 동안 바닥 밝기가 갑자기 꺼지지 않아야 한다.
- 해가 아직 지평선 아래에 있을 때도 새벽 하늘의 산란광이 존재해야 한다.
- 저녁에도 같은 원리로 직사광과 밤 사이를 연결한다.
- 강한 달빛 때문에 밤중보다 새벽이 부자연스럽게 훨씬 어두운 상태를 피한다.
- 달의 위상·실제 천문 계산을 구현한 시스템은 아니다. 현재는 플레이 가독성과 시간대의 분위기를 위한 조명 모델이다.

### 15.4 현재 시간·조명 설정

| 설정 | 값 |
|---|---:|
| 시작 시간 | 13:00 |
| 자동 시간 진행 | 켜짐 |
| 기본 하루 길이 | 현실 시간 20분 |
| 기본 배속 | 1배 |

### 15.5 조명 연결

- 시간 제어의 중심은 `31 SKY - Tenkoku textures URP adapter`의 `VillageDayNightCycle`이다.
- 태양은 현재 `42 LOOK - Standard demo daylight` 오브젝트의 Light를 연결해 사용한다. 이름과 달리 현재는 순환 제어를 받는다.
- 예전 `05 Afternoon light`를 추가로 켜 이중 태양을 만들지 않는다.
- 태양과 달 중 한 개만 주 방향광으로 활성화한다.
- 밤 Volume은 밤 가중치에 따라 섞고, 가로등 밝기와 발광도 함께 조절한다.
- 현재 Trilight 색 변화는 연속 갱신한다. 10초마다 sky probe를 다시 계산하던 처리는 제거했다.

## 16. 그림자 안정성

### 16.1 현재 설정

| 설정 | 현재 값 |
|---|---:|
| URP Shadow Distance | 800m |
| Main Light Shadowmap Resolution | 4,096 |
| Shadow Cascades | 4 |
| Cascade split 비율 | 0.045 / 0.15 / 0.40 |
| Cascade Border | 0.20 |
| Depth Bias | 1.0 |
| Normal Bias | 0.65 |

800m는 모든 거리의 나무에 무제한 실시간 그림자가 적용된다는 의미가 아니다. 더 먼 풍경은 재질·원경 색·지형·안개로 깊이를 유지한다.

### 16.2 반드시 지킬 동작

- 화면 밖으로 나간 물체도 화면 안에 그림자를 드리울 수 있다.
- 본체의 카메라 프러스텀 판정만으로 그림자 생성까지 제거하지 않는다.
- 배치 렌더러는 필요한 화면 밖 캐스터를 `ShadowsOnly`로 제출한다.
- 원거리 숲 렌더러의 `shadowDistance=0`을 무심코 되살리지 않는다.
- 낮은 바이어스의 자기 그림자 노이즈와 과도한 바이어스의 떠 있는 그림자를 함께 검수한다.
- 시점 이동, LOD 전환, 시간 진행, 일출·일몰을 따로 테스트한다.

### 16.3 깜빡임 진단 순서

1. F8로 시간을 고정하고 가만히 서서 확인한다.
2. 같은 시간에서 카메라만 회전하거나 이동한다.
3. 시간만 진행시키고 카메라는 고정한다.
4. 원본 메시와 원거리 LOD의 전환 구간을 확인한다.
5. 태양·달·예전 방향광이 중복 활성화되는지 확인한다.
6. 그림자 거리, 캐스케이드, 바이어스, 알파 클리핑, 바람 변형을 점검한다.

현재 보완을 모든 상황의 깜빡임이 완전히 해소됐다는 보증으로 기록하지 않는다. 실제 플레이에서 재현 구간을 특정해 검수한다.

## 17. 캐릭터·카메라·시간 조작

### 17.1 탐험 캐릭터

- 이전 프로토타입의 조작 가능한 캐릭터를 재사용한다.
- 시작 위치는 마을 입구에서 마을을 먼저 둘러보기 좋은 곳으로 둔다.
- WASD 이동이 다른 디버그 입력이나 UI와 충돌하지 않게 한다.
- V로 1인칭과 3인칭을 전환한다.
- 1인칭에서 아래를 보면 하체가 보이고, 머리 내부가 카메라를 가리지 않게 한다.
- 3인칭은 마우스 휠로 줌인·줌아웃한다.
- 1인칭 시점과 캐릭터 지면 충돌을 함께 검수한다.

### 17.2 현재 주요 단축키

| 입력 | 기능 |
|---|---|
| WASD | 이동 |
| 마우스 | 시점 회전 |
| Left Shift | 달리기 |
| V | 1인칭 / 3인칭 전환 |
| 마우스 휠 | 3인칭 카메라 줌 |
| R | 시작 위치로 복귀 |
| Esc | 탐험 조작·커서 잠금 전환 |
| F2 | 레트로 화면 프리셋 순환 |

| `[` / `]` 길게 | 시간 연속 이동 |
| Shift + 괄호 키 길게 | 더 빠른 수동 시간 이동 |

- F8 정지 중 배속 변경은 선택 배속만 바꾼다. 재개는 F8로 한다.
- 입력 칸에서 글을 쓰는 중에는 시간 단축키가 실행되지 않게 한다.
- 새 단축키를 만들 때 기존 F2 화면 효과, F5 저장, F9 불러오기 등과의 충돌을 확인한다.

원본 프로젝트 `zombie-extraction`의 CedarRetroScreen 계열 효과를 현재 프로젝트의 URP RenderGraph에 맞춰 가져오는 요구가 있었다.

## 19. 최적화 기준

### 19.1 우선순위

1. 현재 병목과 실제 화면을 확인한다.
2. 불필요한 반복 검사·할당·조명 계산을 제거한다.
3. 인스턴싱, 공간 단위 컬링, 원본 LOD를 활용한다.
4. 먼 거리의 메시·그림자·작은 장식 비용을 조정한다.
5. 시각적 영향이 큰 밀도 감소는 전후 비교 후 결정한다.

사용자가 만족한 군집 밀도와 분위기를 먼저 무너뜨리는 방식으로 최적화하지 않는다.

### 19.2 현재 설정 스냅샷

| 항목 | 현재 값 |
|---|---:|
| Terrain tree distance | 3,300m |
| Terrain tree billboard distance | 500m |
| Tree cross-fade length | 50m |
| Tree maximum full LOD count | 1,024 |
| Quality LOD bias | 1.4 |
| Terrain heightmap pixel error | 4 |
| Terrain basemap distance | 1,200m |
| Terrain detail distance | 160m |
| 작은 돌 / 중간 바위 / 큰 바위 표시 거리 | 170 / 320 / 650m |
| 추가 바위의 그림자 판정 거리 기준 | 110m, 화면에 들어오는 투영 영역도 고려 |

### 19.3 적용한 구조 개선

- 추가 바위는 매 카메라에서 전체 16,959묶음을 상세 검사하는 대신 공간 구역으로 먼저 거른다.
- 최적화 당시 세 시점에서 상세 검사 수는 896 / 708 / 159묶음이었다.
- 해당 검증에서 본체 표시 수는 기존 전체 검사와 각각 121 / 67 / 30으로 일치했다.
- 이 수치는 **컬링 검사 수의 감소**이며 FPS 개선율이 아니다.
- 이후 화면 밖 그림자 캐스터 보존 로직이 추가돼 시점에 따라 그림자용 제출은 늘어날 수 있다.
- 라이트 프로브가 없는 씬에서는 바위 인스턴스마다 불필요한 프로브 보간을 요청하지 않는다.
- 배치 렌더러의 프러스텀 Plane 배열을 재사용한다.
- 나무·추가 바위 개수를 유지하면서 LOD와 지형 정밀도를 조절했다.

### 19.4 성능 확인의 범위

현재 문서 기준으로 검증된 것은 설정 적용, 컬링 표시 일치, 시간 조절 로직 등의 동작이다. 정식 빌드에서 특정 FPS를 달성했다고 주장하지 않는다. 임시 카메라 렌더 시간이나 Editor의 오래된 통계 값을 플레이 FPS로 바꾸어 기록하지 않는다.

후속 측정은 같은 해상도, 같은 카메라, 같은 시간대, 같은 레트로 프리셋에서 수행한다. CPU/GPU 프레임 시간, 드로콜, 삼각형, 그림자, 식생 오버드로를 함께 본다. 다음 검토 후보는 건물·담장·소품의 구역별 배칭이다.

## 21. 변경·재생성 절차

### 21.1 작업 전

1. 활성 프로젝트와 씬이 맞는지 확인한다.
2. 사용자가 현재 플레이 중인지, 저장하지 않은 편집이 있는지 확인한다.
3. 씬·TerrainData·변경할 머티리얼 또는 URP 설정의 백업을 만든다.
4. 현재 시간대, 카메라 위치, 화면 효과, 품질 설정을 기록한다.
5. 이번 변경이 배치·지형·머티리얼·라이팅 중 어디에 해당하는지 범위를 정한다.

### 21.2 배치 변경

1. 최신 웹 도면과 JSON을 확인한다.
2. 건물·도로·목책·필지·강의 기준 좌표를 맞춘다.
3. 공유 마스크를 갱신한다.
4. 지면 페인팅, 농작물, 울타리, 식생 제외 영역을 함께 반영한다.
5. 옛 위치에 남은 인스턴스·텍스처·콜라이더를 검사한다.
6. 통행과 접지를 검수한다.

### 21.3 식생·질감 변경

1. 원본 데모와 현재 씬을 같은 화면 효과 상태에서 비교한다.
2. 원본 에셋의 스케일·머티리얼·LOD 연결을 확인한다.
3. 기본 낮은 풀과 군집 식생을 구분한다.
4. 도로·필지·집·강 보호 마스크를 적용한다.
5. 초원과 숲 내부에 다른 규칙을 적용한다.
6. 근거리, 중거리, 원거리에서 누락·반복·뜸·과밀을 검사한다.

### 21.4 라이팅 변경

1. 현재 시간 순환이 광원·환경광을 덮어쓰는지 확인한다.
2. 태양·달·이전 방향광의 활성 상태를 확인한다.
3. 낮, 밤, 해 뜨기 직전, 해 진 직후를 각각 확인한다.
4. F8 시간 고정과 배속 진행을 모두 시험한다.
5. 그림자 안정성과 가로등 제한을 확인한다.
6. 검사 후 사용자가 볼 기본 시각과 배속으로 복원하고 저장한다.

### 21.5 결과 보고

- 무엇을 바꿨는지, 왜 바꿨는지, 실제로 어디까지 확인했는지를 기록한다.
- 수치 검증과 시각 검증, 플레이 성능 검증을 구분한다.
- 검증하지 않은 FPS, 모든 모델의 라이선스, 모든 경계의 완벽한 품질을 확정 표현하지 않는다.
- 사용자가 빠른 시각 피드백을 원할 때 불필요한 전체 재생성·반복 검사를 피한다.

## 24. GitHub 문서 관리

### 24.1 권장 위치

이 파일을 `Documentation/ENVIRONMENT_GUIDELINES.md`로 유지하고 저장소의 README에서 연결한다. 문서 제목은 **환경 구축 가이드라인**으로 표시한다.

```markdown
- [환경 구축 가이드라인](Documentation/ENVIRONMENT_GUIDELINES.md)
```

문서 저장소는 [judink/naturecreate](https://github.com/judink/naturecreate)다. README와 이 가이드라인을 관리하며, 본문에 명시된 Unity 프로젝트 내부 경로는 구현 위치를 설명하는 참조다. 해당 씬·스크립트·에셋 원본이 이 문서 저장소에 포함된다는 뜻은 아니다.

### 24.2 공개 문서에 넣을 내용

- 이 가이드, 직접 작성한 설명과 검수표.
- 날짜와 조건이 명시된 전후 비교 이미지.
- 사용한 패키지 이름과 버전, 프로젝트 내부 상대 경로.
- 실제 검증 결과와 남은 과제.

참고 이미지와 에셋은 문서에서 참조하는 것과 원본 파일을 재배포하는 것을 구분한다. 팩 전체, 내려받은 ZIP, 유료·제3자 모델 원본을 문서와 함께 자동으로 업로드하지 않는다. 필요한 에셋 사용 조건과 배포 허용 범위는 해당 에셋의 출처에서 따로 확인한다.

### 24.3 업데이트 규칙

- 승인된 큰 변경마다 기준일과 관련 설정 표를 갱신한다.
- 사용자가 철회한 방향은 현재 규칙에서 제거하고 변경 이력에 남긴다.
- 임시 실험값을 확정 기준처럼 기록하지 않는다.
- 실제 씬과 문서가 다르면 씬 상태를 확인한 뒤 차이를 명시한다.
- 절차적 재생성 도구의 입력·출력·백업 기준이 바뀌면 데이터 흐름도 함께 갱신한다.

이 문서는 과거 명령을 그대로 재실행하는 목록이 아니라, 현재 만족한 환경을 유지하며 다음 수정을 진행하기 위한 기준이다.
